# ADR: フィルタ選択は版つき JSON で永続化し、トレイは統合一覧をカテゴリ別サブメニューで出す

- **決定日**: 2026-09-30（Issue #65）
- **記録日**: 2026-09-30（ADR 化）
- **ステータス**: Accepted（実機 macOS / Windows のトレイ操作は確認待ち。「結果・トレードオフ」参照）

## 文脈（問題）

- advanced フィルタ（sensus 30 種）の選択・強度・payload パラメータは `VisionFilterState`
  のメモリ上にしかなく、再起動すると消えた。色覚だけは `FilterService`（強度、#57）と
  `SettingsService.filterType` が残していた。
- トレイから選べるのは色覚 4 型だけで、advanced フィルタや -omaly はウィンドウを開かないと
  選べなかった。
- sensus のフィルタ id やパラメータ定義は今後も変わりうる。保存値がそれに引きずられて
  起動できなくなってはならない。

## 決定

1. **`VisionFilterState` の「残す部分」を値オブジェクト `VisionFilterSnapshot` に切り出し、
   版つき JSON（`settings.visionFilter`）として `SharedPreferences` に保存する。**
   保存するのは選択（id・体験プリセット id・色覚クイック選択の型）とフィルタ id ごとの強度・
   payload の記憶。原画比較などの一時状態は保存しない。seed（u64）は 10 進文字列。
2. **カタログ＝定義、state＝実行時の分離を保ち、保存値は読み込み時にカタログへ照らして補正する。**
   未知 id・定義に無いパラメータは捨て、範囲外は min/max に丸め、型違い・NaN・未知の
   選択肢は既定値に戻し、欠けたパラメータは既定値で埋める。版違い・壊れた JSON は丸ごと捨てる。
   例外は起動を止めない。
3. **復元は既存の色覚シードの後に上書きする。** 復元できる保存値があればそれが勝ち、無い・
   空・壊れているときは state に触れない（初回起動の deuteranomaly シードなどの既定を保つ）。
   体験プリセットは、今の体験一覧にありフィルタが一致するときだけプリセット選択として戻す。
4. **書き込みは `FilterService` の強度（#57）と同じ作法**（300ms デバウンス・終了経路で
   `flush()`・失敗は握りつぶす）。JSON が直前と同じ通知では書かない。
5. **トレイには統合フィルタ一覧（33 行、#72）を「高度なフィルタ」の入れ子サブメニュー
   （カテゴリ別）として出す。** 選択はウィンドウ内一覧と同じ入口 `applyFilterListEntry` を通り、
   チェックは `selectedFilterListEntry(visionFilterState)` から決める。トレイとウィンドウ内 UI
   は同じ `VisionFilterState` を見るので双方向に同期する。
6. **ラベルは ARB（ja/en）から解決した `TrayMenuLabels` で受け取り、`updateLocalization` で
   言語変更に追従する**（#82 の作法）。`TrayMenuLabels` は `tray_menu_labels.dart` に分け、
   `l10n_extensions.dart` ⇄ `filter_list_selection.dart` ⇄ `tray_service.dart` の循環を避ける。
7. **メニュー構造が直前にネイティブへ送ったものと等しければ送り直さない**（スライダー操作で
   `VisionFilterState` が連続通知されるため）。「直前に送ったもの」は送信の完了を待たず
   に記録する（送信中に A→B→A と変わっても最後の状態を送るため）。クリック直後だけは、
   ネイティブが先にチェックを反転させる環境に備えて必ず送り直す。
8. **トップレベルの色覚項目のチェックも統合一覧と同じ選択行から決める。** 色覚の base 型
   （Protanopia 等）を高度なフィルタ側から選んでも同名のトップレベル項目に点灯する
   （ウィンドウ内一覧が同じカタログ id の行を点灯させるのと同じ）。体験プリセット選択中は
   トレイにプリセットを出さないので、何もチェックしない。
9. **フィルタ切替は `LoupeWindowController`（クリックスルー・最前面・モード、#63）に触れない。**

## 代替案

- **色覚と同じく個別キーで保存する**: 選択・強度・payload・由来の整合を保つのが難しく、
  補正も分散する。1 つの JSON にまとめれば「保存内容はこの型の写し」と言い切れ、版で丸ごと
  捨てられる。
- **保存値をそのまま信じる（補正しない）**: sensus 側の定義変更で範囲外・未知の値が
  `VisionFilterState` に入り、描画時に失敗しうる。カタログが正本である以上、読み込み口で
  正規化する。
- **カテゴリ見出しをトップレベルに 7 つ並べる**: メニューが長くなる。1 つの「高度なフィルタ」
  の下にまとめる。
- **トレイ独自のフィルタ一覧を持つ**: ウィンドウ内一覧との二重管理になり、選択の入口・
  チェックの判定がずれる。統合一覧（#72）をそのまま使う。
- **毎回ネイティブへメニューを送る**: 実装は単純だが、スライダーのドラッグ中に 33 行 +
  カテゴリを作り直し続ける。構造の値等価で抑止する。

## 根拠

- 状態の正本は `VisionFilterState` の 1 つのまま、保存・トレイはその写し・入口の 1 つ
  という関係にできる（#60 の「唯一の正本」方針の延長）。
- 起動の堅牢性は「読み込み口で補正する」ことで、sensus の変更から切り離せる。

## 結果・トレードオフ

- 保存 JSON の形を変えるときは `kVisionFilterSnapshotVersion` を上げる。古い版は丸ごと
  捨てられ、既定値で起動する（移行は書かない）。
- 復元中に sensus 呼び出しが例外を投げても起動は止まらない。`VisionFilterState.restore` が
  失敗時に呼び出し前の状態へ巻き戻し、store が握って色覚シードのまま起動する。
- 選択の保存先が 2 か所になっている: `SettingsService.filterType` は初回起動の判定と旧版
  からの移行（色覚シード）のために残し、選択の正本は `settings.visionFilter`（復元は後者が
  勝つ）。統一は #32（状態モデルの統合）で行う。
- advanced 選択中の `FilterService` は従来どおり古いまま（消費側が `isColorQuickSelection`
  で判定する）。復元時に色覚クイック選択なら `FilterService.applyFilter` も呼んで揃える。
- トレイの入れ子サブメニューの実機表示（macOS メニューバー・Windows 通知領域）は、この
  開発環境では目視できない。構造と操作は `tray_manager` の MethodChannel モックで検証し、
  実機確認は kako-jun の環境に委ねる。
