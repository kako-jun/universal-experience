# ADR: 重いプレビュー描画は低解像度で先に見せ、描いた結果をメモリに覚える

- **決定日**: 2026-11-14（Issue #185）
- **記録日**: 2026-11-14
- **ステータス**: Accepted

## 文脈（問題）

プレビュー（Before/After）は sensus の CPU `apply()` で 1024px を描く（`kCanonicalSampleSize`）。
starbursts は明るい画素の数に比例して重く、明るい画像では 1 回に数十秒かかる（実機で約 44 秒、#185）。
ネイティブの描画は途中で止められず、描画は 1 本ずつ流す（#85）ので、その間は何を操作してもプレビューが
変わらない。sensus 側の高速化（kako-jun/sensus#196）が入るまで、ue の側で「止まって見える」時間を縮めたい。

## 決定

1. **低解像度の仮表示**: 重い入力（starbursts を含む、または直前のフル解像度の描画が 2 秒を越えた）は、
   先に 512px（`kProvisionalPreviewSize`）へ縮めた元画像で描いて表示し、続けてフル解像度で描いて差し替える。
   starbursts の計算量は一辺のほぼ 3 乗なので、仮表示は 1/8 程度で出る（実機で 10 秒以内）。
   - 仮表示の間は札に「描画中…（低解像度の仮表示）」と出し、**書き出しボタンを出さない**（低解像度の
     画像に症状名を焼いて保存させない）。
   - **見え方が少し違う**: 画素数で効き方が決まるフィルタ（`kCanonicalSampleSize` の doc の一覧）は、
     仮表示の間だけフル解像度と見え方が違う。仮表示であることは札で示し、フル解像度で必ず差し替える。
   - 仮表示を描いている間に新しい要求・キャッシュからの表示に追い越されたら、仮表示は貼らず、フル解像度も
     描かずに次の要求へ譲る。
2. **描画結果のキャッシュ**: フル解像度の結果を、入力（元画像・解像度・フィルタ構成・強度）を鍵にした
   LRU で覚える（`PreviewRenderCache`）。付ける → 外す → 付けるで描き直さない。長い描画の最中でも、
   キャッシュにある入力へ戻せばすぐ表示する。
   - **メモリの上限**: 6 件（1024px の RGBA で 1 枚 4 MiB、約 24 MiB）。越えたら最も長く使っていないものから捨てる。
   - **ディスクには書かない**。ビューが外れたら全部捨てる。
   - **ユーザー画像**: 別の画像へ替えたら、前の画像から描いた結果を捨てる（遅れて終わった前の画像の
     描画も入れない）。サンプル画像の分は残す。
   - 仮表示（512px）は覚えない。A → B → A をフル解像度が描き上がる前に行き来すると仮表示を描き直すが、
     1/8 程度なので許容する。
3. **元画像の読み込みを描画から分ける**: サンプルを替えたら、after の重い描画を待たずに元画像を差し替える。
4. **原画そのままの要求は描画しない**: フィルタの全解除・原画比較（ホットキー・ルーペ HUD）は after = 原画
   なので、重い描画が走っていても待たせず原画の複製をすぐ出す（数十秒待たされると固まったのと同じ見え方に
   なる）。強度 0 は「効果なし」として扱う（複数層の合成が強度 0 の層を除くのと同じ）。2×2 比較も、原画比較中
   （強さ 0・土台なし）は同じようにする。

## 2×2 比較（`ColorVisionCompareView`）には 1〜3 を入れない

- 2×2 は元画像を表示しないので、3 の効果が無い（4 の原画比較は 2×2 にも入れた）。
- 色覚以外の層の「土台」は従来から入力ごとに使い回しており（#122）、色覚の強さだけを動かす操作では
  再合成しない。4 セルの色覚 1 段は軽い（数十〜数百 ms）。
- 制約: 土台に starbursts を含む最初の描画は、今も数十秒かかる（その間は見出し行に「描画中…」が出る）。
  仮表示を入れるには 4 セル × 2 段の描画と書き出しの扱いを決める必要があり、sensus 側の高速化
  （kako-jun/sensus#196）を先に待つ。

## 却下した案

- **描画を途中で打ち切る**: sensus の `apply()` は途中で止める口を持たない（FFI の 1 呼び出し）。
- **常に低解像度で描く**: 画素数で効き方が決まるフィルタの見え方が変わり、書き出しの解像度も落ちる。
