# ue 自身の UI のアクセシビリティ（チェックリスト）

ue は「見え方の違いを体験する」アプリだが、使う人には当事者（低視力・色覚特性・聴覚障害・前庭障害など）や
高齢の人もいる。この文書は **ue 自身の UI** がそうした人にも使えるかを、項目ごとに「現状」と
「直したか」で記録する（#45）。新しい画面・部品を足したときは、この表の該当する行を見直す。

- 機械で確かめられる項目は `test/accessibility_guidelines_test.dart`（Flutter 標準のガイドライン）と
  `test/accessibility_semantics_test.dart`（読み上げの名前・値・役割・選択状態・画像の代替テキスト・視差効果）が守る。
  Tab 順・Enter/Space・Esc は `test/home_screen_layout_test.dart` が持つ。
- 実機でしか確かめられない項目は **【kako-jun 実機】** と付けた。headless のテストは通っても、
  実際の読み上げ（VoiceOver / TalkBack / NVDA / Orca）の順序・言い回しは保証しない。特に `liveRegion`
  （準備中・描画失敗・強度の注意）がデスクトップの embedder で実際に読まれるかは、headless では
  Semantics のフラグが付いていることしか確かめられない。
- 非スコープ: 新機能の追加。ここは既存 UI の監査と是正だけ。

## 1. 監査の対象と基準

| 観点 | 基準 | 機械検証 |
|---|---|---|
| 読み上げの名前・役割 | 操作できる要素すべてに名前がある。スライダー/ドロップダウンは名前と値、見出しは見出し、画像は代替テキスト | `labeledTapTargetGuideline`、Semantics ツリーの assert |
| コントラスト | 通常の文字 4.5:1、大きい文字 3:1（WCAG 2.x AA） | `textContrastGuideline`（ライト/ダーク/ハイコントラスト 2 種 × ja/en） |
| タップ領域 | 48 × 48 dp 以上（Material / Android の基準） | `androidTapTargetGuideline`（広幅/狭幅 × ja/en） |
| キーボード | マウスなしで、主要な操作（選ぶ・調整・比較・書き出し・ダイアログ）に届く。閉じたあと操作が続けられる | `home_screen_layout_test.dart`、`accessibility_semantics_test.dart` |
| 色だけに頼らない | 選択・状態・注意は、形（アイコン）・太さ・文言でも伝える | Semantics の selected、アイコンの有無 |
| 動き・点滅 | 点滅は使わない。動きは OS の「視差効果を減らす」に従う | `disableAnimations` の assert（画像ドロップ枠・ルーペ HUD のフェード・選択行のスクロール） |

## 3. 既知の制約（直せない / 直さないと決めたもの）

| # | 内容 | 理由 | 扱い |
|---|---|---|---|
| 1 | 一覧のスクロールで端に半分見切れたカテゴリチップ（例: 視野・光/透明度）は、その瞬間のタップ領域が 48 dp に満たない（62 × 20 dp） | 見切れは Flutter のスクロール領域のクリップによる。スクロールすれば全体が出て 48 dp になる | `accessibility_guidelines_test.dart` では、見切れの起きない状態（色覚を選択）を測る。見切れた状態は測定対象外 |
| 2 | 通常テーマ（ライト/ダーク）の `outlineVariant`（区切り・枠）は背景に対して約 1.6:1 | 装飾の区切り線・カード枠。操作できる部品の識別は枠でなく文字・アイコンが担う。ハイコントラストでは基準以上 | 通常テーマは装飾として許容。ハイコントラストで読める |
| 3 | スライダーの読み上げは「強さ / 100% / 100%」のように値が 2 回読まれうる | Flutter の `Slider` が名前の入口を持たず、`label`（値の吹き出し）と値がそれぞれ出る。名前を載せるには `MergeSemantics` で束ねるしかない | 名前が欠けるよりは重複を許容 |
| 4 | Linux など OS が `MediaQuery.highContrast` を報告しない環境では、ハイコントラストに自動で切り替わらない | Flutter の対応範囲（DESIGN.md §2.1） | 手動切替は未実装（新機能のため非スコープ） |
| 5 | flutter_test の文字は Ahem（塗りつぶし）で描かれる | テスト環境の制約 | コントラストは前景・背景の色の組を測るので、実フォントでも結果は変わらない |

## 4. 【kako-jun 実機】で確かめる項目

headless では確かめられない。次の回に実機で確認する。

1. **スクリーンリーダー**（macOS VoiceOver / Windows NVDA / Android TalkBack / Linux Orca）で、主要な操作を
   読み上げだけで最後までできる: 画像を選ぶ → 見え方を選ぶ → 強さを変える → 2×2 比較 → 書き出し。
   スライダーが「強さ」と値で読まれる、選んだ行が「選択中」と読まれる、画像に名前がある、の 3 点を見る。
   あわせて、**準備中・描画失敗・強度の注意が状態変化として読み上げられるか**を見る（macOS の VoiceOver。
   デスクトップの embedder で `liveRegion` が読まれるかは headless では保証できず、読まれない環境では
   画像の代替テキストが現れることだけが手がかりになる）。
2. **キーボードだけ**で全画面を通す: Tab の順序が左 → 中央 → 右、`/` で検索、↑↓ / ←→、Esc でダイアログが
   閉じる、閉じたあと押したボタンに戻る。
3. **OS のハイコントラスト設定**を ON にして、ハイコントラストのテーマに切り替わり、文字・枠が読める
   （macOS の「コントラストを上げる」、Windows のコントラストテーマ）。
4. **OS の「視差効果を減らす」**を ON にして、ルーペ HUD のフェード・一覧のスクロールが即時になる。
5. **トレイメニュー**の読み上げとキーボード操作、**グローバルホットキー**の実発火。
6. **文字サイズの拡大**（OS / ブラウザの拡大）で、折り返し・はみ出しが起きない（ue は `textTheme` のロールで
   文字を指定しており、倍率で崩れないかは実機で見るのが早い）。
