# Universal Experience

色覚障害・聴覚障害など、複数の感覚障害をシミュレーションできるアクセシビリティ体験アプリ。

**「すべての感覚を、すべての人に。」**

## 機能

### 色覚障害シミュレーション

- Protanopia（1型色覚・赤色盲）
- Deuteranopia（2型色覚・緑色盲）
- Tritanopia（3型色覚・青黄色盲）
- Achromatopsia（全色盲）
- Protanomaly / Deuteranomaly / Tritanomaly（各異常3色覚。錐体機能の部分低下）

色覚変換アルゴリズムの正本は別 crate
[`sensus-core`](https://crates.io/crates/sensus-core)（Rust）に一元化しており、
ue はそれを flutter_rust_bridge 経由で消費する薄いブリッジです（ue 側で LMS 等の
変換ロジックを再実装する方針は取りません）。フィルタの見え方は sensus の CPU
`apply()`（`lib/rendering/cpu_vision_renderer.dart`）で計算し、強度調整も可能です。
強度は**フィルタごとに個別記憶**します（色覚は -omaly と -opia を別々に。`VisionFilterState`、#57・#117）。まだ選んだ
ことのないタイプを選ぶと推奨強度（-opia / achromatopsia は 1.0、-omaly は
0.6）が初期値になり、フィルタを切り替えても切替前のタイプの強度は保持されます。

> 色覚 3 型（protanopia/deuteranopia/tritanopia）の中間 strength は、sensus 0.6 の
> Machado 2009 11 段 severity テーブルをグリッド間で区分線形補間した正本値と一致
> します。現行のプレビュー描画経路（sensus の CPU `apply()`、#85）は sensus-core の
> 公開関数をそのまま呼ぶため、この一致は自動的に保証されます。GPU 経路
> （`ShaderFilter`。ライブ画面キャプチャ向けに残置、現状 production 未使用）は
> sensus と別に Dart 側で行列を再現する必要があり、`rust/src/color_matrix_gen.rs`
> が sensus-core の公開関数から 11 グリッド点を汲み出して `tools/color_matrices.g.json`
> に書き出し、`tools/generate_color_matrices.dart` が `lib/rendering/
> color_matrices.g.dart`（Dart 定数）へ変換、`ShaderFilter.resolveSeverityMatrix()`
> が sensus と同じ補間式でグリッド間を解決します（#59）。手書きの行列値は持ちません。

> 旧バージョンは OS 全体へ system-wide フィルタを適用する独自プラグイン
> （`plugins/color_vision_filter`）と ue 内 LMS 実装を持っていましたが、
> sensus 一元化に伴い撤去しました。ライブ画面（他アプリ含む全画面）への
> 適用は、画面キャプチャ経路の実装後に対応予定です。

> before / after の比較プレビューは、sensus が公開する全 30 種すべてで実際に
> 描画できます（色覚のクイック選択・advanced カタログ・体験プリセットは、この
> 同じ 30 種への 3 つの選び方に過ぎません — 重複カウントではありません）。描画は sensus
> の CPU `apply()` 経由（#85）で、固定の正準サイズ（1024px）で描画してから
> 表示側で拡大縮小します。GPU シェーダは将来のライブ画面キャプチャ機能向けに
> 残してありますが、現状はどこからも呼ばれていません。プレビューの描画対象は
> `VisionFilterState` の現在の選択（色覚のクイック選択・advanced カタログ・
> 体験プリセットのいずれで選んでも一本化される）を唯一の正本にします（#60）。
> vertigo / bppv_rotation のような時間依存フィルタは、プレビューでは動きのない
> 静止フレームになります（その旨は注記します）。
>
> 色覚のクイック選択・advanced カタログ・体験プリセットは選択の起源として
> 区別され（`lib/services/color_vision_selection.dart`）、色覚のクイック選択が
> 起点のときだけプレビューの強度は色覚タイプごとの記憶（#57）を使います
> （それ以外は advanced の strength スライダー自体の値）。advanced/プリセットを
> 見ている間は色覚のクイック選択チップを点灯させず、advanced 側の strength
> スライダーも色覚クイック選択中は出しません（動かしても反映されない
> スライダーを見せないため）。-omaly（protanomaly 等）を選んだときは、
> 見出し・export の caption・ファイル名にも -omaly の名前を正しく出します。

### 視覚 advanced フィルタ（sensus カタログ）

sensus が提供する**計 30 種**（上記の色覚型を含む。屈折／視野欠損／
光・透明度／前庭・めまい／眼精疲労 等）の視覚フィルタをカタログから
カテゴリ別に選択し、パラメータ・強度を調整できます。フィルタ定義の正本は
sensus-core であり、ue はカタログ（`lib/models/vision_filter_catalog.dart`）
から引きます。選択・パラメータ調整は `VisionFilterState` に反映され、
プレビューにもそのまま反映されます（#60）。

強度・パラメータは**フィルタごとに記憶**します（#77）。まだ選んだことのない
フィルタを選ぶと sensus の推奨強度（`recommended_strength()`。例:
tunnel_vision は 0.5）が初期値になり、フィルタを切り替えても切替前のフィルタの
値は保持されます。「推奨値に戻す」ボタンで強度・パラメータを推奨値・既定値へ
戻せます。

内部では複数のフィルタを重ねて適用できる状態（最大 5 層。色覚は同時に 1 つ、適用順は症状の段で固定）
とプレビューの合成経路まで入っています（#119）。複数選択の操作 UI はこれからで（#120）、画面上の
見た目と操作は当面これまでどおり 1 つずつ選ぶ形です。

**選んだフィルタ・強度・パラメータは再起動後も残ります**（#65）。前回終了時の
選択（色覚・advanced・体験プリセット）とフィルタごとの記憶が起動時に復元され、
保存値が壊れていたり、sensus 側でフィルタやパラメータが変わって範囲外・未知に
なっていても、その部分だけを既定値へ戻して起動します（起動は止まりません）。
タスクトレイの「高度なフィルタ」サブメニューからも、カテゴリ別にすべての
フィルタ（色覚 7 型 + advanced 30 種）を切り替えられ、選択中のものにチェックが
付きます。ウィンドウ内の選択とトレイは同じ状態を見ているので、どちらで選んでも
もう一方に反映されます。フィルタの切替はクリックスルーなどのウィンドウ設定に
影響しません。

強度の上限付近に注意が要るフィルタでは、スライダに印と注記を出します（#66）。
例えば tunnel_vision は強さ 100% で視野のほぼすべてを失った、最も進行した段階を
表すため、80% の位置に印を付け、そこから先は「ほぼ真っ暗になるのは最も進行した
段階を再現しているためで、故障ではない」旨の警告に切り替わります。対象と閾値は
`lib/models/vision_filter_contract_notes.dart`、文言は ARB です。

受診喚起（早期受診が望ましい・即受診が必要 等）は sensus-core の
`Filter::urgency()` を唯一の正本にします（#76）。ue 独自の段階分類は持たず、
UI にも「緊急度：高」のような段階名は出しません。喚起がある場合は喚起文だけを
専用の注記ブロック（`ConsultNoticeBlock`）で表示し、条件付きで喚起が強まる
ケース（`urgency_escalation()`。例: 「反復・重症の発作なら受診を」）も
emergency/earlyConsultation の見出しに分けて併記します。喚起文からは診療科名
を出しません（めまい系フィルタは眼科の話ではないため）。末尾には「医学的な
診断ではない・医療監修を受けたものではない」旨と、根拠として
シミュレーションライブラリ sensus の公開資料（[Medical notes 節](https://github.com/kako-jun/sensus/blob/main/docs/overview.md#medical-notes-when-to-see-a-doctor)）
への参照を必ず添えます。この喚起の解決（`resolveConsultNotice`）と表示
ウィジェット（`ConsultNoticeBlock`）は、advanced フィルタのパネル・体験
プリセットのカード・PNG エクスポートの 3 か所で共有する唯一の経路です。

### 体験プリセット（複合症状）

複数の感覚にまたがる複合症状を、ワンタップで適用できる 4 つのプリセットを
用意しています:

- メニエール病（meniere）
- 良性発作性頭位めまい症（BPPV）
- 前庭神経炎（vestibular neuritis）
- 迷路炎（labyrinthitis）

各プリセットは視覚フィルタを選択状態にし、強度・パラメータは常に sensus の
推奨値・既定値にして before/after プレビューに反映します（#60。強度は #77 で
「常に 1.0」から「常に推奨値」に変更）。受診喚起の注記も、advanced フィルタと
全く同じ解決経路・表示ウィジェット（`resolveConsultNotice` /
`ConsultNoticeBlock`）で表示します（#76）。escalation は体験の視覚フィルタ
（`Experience.vision`）から取得します。喚起文・escalation は各プリセット
カードに出しますが、免責文・根拠 URL はカードごとに繰り返さず、「体験
プリセット」セクションの末尾に 1 回だけ表示します（同セクション内にどれか
1 枚でも喚起があるときのみ）。聴覚症状を含む体験
（メニエール病・迷路炎）には「聴覚症状も含む」注記を出しますが、
**音声再生は未実装**です。プリセットの選択は体験 id（`meniere` 等）で保持する
ため、メニエール病と迷路炎（どちらも内部的には同じ vertigo フィルタ）を同時に
選択中と誤表示することはありません。また、プリセットのタップは色覚のクイック
選択（`FilterService`）を変更しません — 両者は独立に選択を保持します。
プリセットの組み合わせ（どの視覚・聴覚フィルタが組になるか）の正本は
sensus-core の `experiences()` です。

### 画像エクスポート（PNG）

フィルタ適用後（after）の画像を、**症状名・強度・日付（ISO・`YYYY-MM-DD`）**
を焼き込んだ PNG として書き出せます。プレビューが描画できるフィルタ（sensus
全 30 種 + 原画表示）はすべてエクスポート可能です。

- **保存先**: ダウンロードフォルダ（実際の `~/Downloads`）。取得できない環境では
  ドキュメントフォルダ。macOS のサンドボックスでは `getDownloadsDirectory()` が
  コンテナ内 `Data/Downloads`（実 `~/Downloads` へのシンボリックリンク）を返すため、
  `macos/Runner/*.entitlements` の `com.apple.security.files.downloads.read-write`
  が無いとリンク先への書き込みが拒否される想定です（修正前の実機挙動は未検証）。
  表示・クリップボード・「フォルダで表示」に使うパスは、シンボリックリンクを
  解決した実パスです。
- **ファイル名**: `ue-<症状 id>-<強度>pct-<日付>_<時刻>.png`
  （例 `ue-protanopia-100pct-2026-06-23_140509.png`）。同名のファイルが既にあれば
  上書きせず `-2`, `-3` … と連番にします。
- 保存後は SnackBar に保存先のフルパスを出し、**「フォルダで表示」**でファイル
  マネージャを開けます（macOS は Finder で選択、Windows は Explorer で選択、
  Linux は含むフォルダを `xdg-open`）。フルパスはクリップボードへもコピーします。

画像そのもののクリップボード書き込み・動画エクスポートは非対応です。

### 色覚 4 型の一覧比較（2×2）

色覚のフィルタ（1型2色覚・2型2色覚・3型2色覚・1色覚と、-omaly の各型、四色覚）を選んでいる間だけ、
プレビューの見出しに **「2×2 で比較」** の切替が出ます。ON にすると、Before / After の代わりに、
**同じ画像・同じ強さ** で色覚 4 型（protanopia・deuteranopia・tritanopia・achromatopsia）を 2×2 に
並べます。見出しは「色覚 4 型の比較」に切り替わります。各セルに型名（日本語 / English）が付き、
強さは現在のスライダーの値を 4 セル共通で使います（描き直している間は、表示中の画像の強さのままです）。
実験的な四色覚は 4 型に含めません。色覚以外のフィルタを選ぶと切替は消えて Before / After に戻ります。

- 原画との比較は、切替を OFF にして Before / After に戻るか、原画へ戻すホットキー（bypass）で行います。
- **書き出し**: 2×2 のまま 1 枚の PNG として書き出せます（保存先・ファイル名の規則は上と同じで、
  `ue-color-vision-compare-<強度>pct-<日付>_<時刻>.png`）。各セルに型名・強度・日付と
  「シミュレーション（近似）」の 1 文を焼き込みます。
- 描画は 1 枚ずつ選んだときと同じ経路（sensus の CPU `apply()`）を 4 回呼びます。判断の経緯は
  `docs/adr/2026-09-30-color-vision-2x2-compare.md`。

> すべての PNG に「シミュレーション（近似）」/ "Simulation (approximation)" の 1 文を
> 焼き込みます（受診喚起の有無にかかわらず常に。単体で共有されても実際の見え方と
> 誤解されないため、#80）。狭い画像でも省略せず、折り返して全文を描きます。
> 実験的なフィルタ（現状は四色覚）には、加えて「実験的な可視化」/
> "Experimental visualization" も焼き込みます。
>
> 受診喚起がある場合は、PNG にもプレビューと同じ喚起文・escalation の行
> （emergency/earlyConsultation の見出し付き）・免責文を焼き込みます（#76）。
> 焼き込む喚起は、実際に export した時点で描画されていたフィルタの
> urgency/escalation から決まります（色覚特性は urgency=none かつ escalation
> も無いため通常は焼き込まれません）。免責文は帯を圧迫しないよう、診断では
> ない旨と根拠の両方を 1 行に収めた短い形（例: "Not a diagnosis; not
> medically reviewed. Source: sensus Medical notes"）にしています（UI の
> 専用ブロックは、医療監修を受けていない旨を含む長い文言 + 参照 URL を
> 表示します）。

### プレビュー原画（サンプル画像集 / ユーザー画像）

before/after プレビューの原画は、内蔵のサンプル画像集（8 種）から選ぶか、
自分の画像を読み込んで試せます（#78）。

- **サンプル画像集**: 路線図（色で区別する複数路線）・凡例付きグラフ
  （赤・緑・青・橙の系列）・信号標識・文字の多い案内板（大小の文字）・
  食べ物や果物（熟した赤・未熟な緑など）・夜景（点光源。広いベタ白は
  置いていません）・奥行きのある風景（手前・中間・遠景）に、日本語の案内板
  （出口・駅・営業中の看板とのりば案内の表）を加えた 8 種類です。
  すべて `tools/generate_samples.dart`（手続き的生成。外部の画像素材は使いません）
  で作った PNG で、図形は自作・手続き生成、人物の顔は入れていません。文字は SIL OFL 1.1 の
  Noto Sans / Noto Sans JP から作ったビットマップフォント（`tools/fonts/`）で
  描いています。出典・ライセンス・生成方法は `assets/samples/README.md` と
  `tools/fonts/README.md` に記載します。奥行きのある風景だけは深度マップ
  （`depth_landscape_depth.png`）も同梱していますが、これは将来の
  depth_aware_blur 体験向けの素材で、現状のプレビューでは使いません
  （配線は Issue #98、`docs/ARCHITECTURE.md`「今後の拡張」参照）。
- **フィルタごとの既定サンプル**: フィルタを選ぶと、そのフィルタに相性の良い
  サンプルへ自動で切り替わります（例: 色覚 → 果物・グラフ・路線図、夜盲/
  starbursts → 夜景、屈折異常/視野欠損 → 案内板・奥行きのある風景）。対応表は
  `lib/models/sample_catalog.dart` の `kRecommendedSampleByFilterId`。
- 手動でサンプルを選ぶと、この自動切り替えは止まります。「おすすめに戻す」で
  自動追従を再開できます。**ユーザー画像を選んでいる間は、フィルタを切り替えても
  自動切り替えは働きません**（自分の画像を見ている最中に勝手に差し替わらない
  ようにするため）。
- **ユーザー画像**: ファイル選択（`file_selector`）・ドラッグ＆ドロップ
  （`desktop_drop`）・クリップボードからの貼り付け（`pasteboard`、下記）に対応します。縦横比を保ったまま正準サイズ（1024px 四方、
  #85）へレターボックス（余白を足して全体を収める。中央クロップはしません
  — 症状の効果はどこに写っているか分からないため、画像の一部を切り捨てない
  方針です）します。**画像は端末の外に送らず、ディスクにも保存しません**
  （デコードしてメモリ上の画像に変換するだけ）。
- **クリップボードからの貼り付け**（#97）: 画像をコピーしてから「貼り付け」
  ボタン、または **Cmd+V（macOS）/ Ctrl+V（Linux）** で、その画像をプレビューの
  原画にできます（ファイル選択と同じ経路で、上限 50MB・長辺 2048px に縮小して
  デコード）。ファイラで画像ファイル（PNG・JPEG・GIF・BMP・WebP）をコピーして
  貼り付けることもできます。クリップボードに画像が無い・大きすぎる・読めない形式
  （画像でないファイルやフォルダだけをコピーした場合を含む）のときは
  メッセージを出し、いま表示している画像は変えません。検索欄などテキスト入力に
  フォーカスがある間は Cmd/Ctrl+V を奪わず、入力欄自身の貼り付けを優先します。
- **初回起動の空状態**: 2 型 3 色覚（deuteranomaly）を推奨強度で選んだ状態
  から始まり、「ほかの見え方を選ぶ」「自分の画像で試す」の 2 つの行動を
  案内するバナーを 1 回だけ表示します（閉じると二度と出ません）。

### 多言語（i18n）

UI は **日本語 / 英語** に対応しています（`flutter_localizations` + ARB）。
既定ではシステムのロケールに追従し、非対応ロケールでは英語へフォールバック
します。画面右上の地球儀ボタンから「自動 / 日本語 / English」を
選べ、選択は永続化されます。変更はフィルタ名・説明を含む画面全体とタスクトレイの
メニューにすぐ反映されます（「自動」のときは OS の言語変更にも追従）。
言語の追加手順と医学用語の訳の確認方針は
[`docs/ADDING_A_LANGUAGE.md`](docs/ADDING_A_LANGUAGE.md) を参照してください。

### アクセシビリティ

ue 自身の UI も、スクリーンリーダー・キーボード・低視力・高齢の人が使えることを目指しています。
スライダー・ドロップダウン・画像に読み上げの名前を付け、タップ領域 48dp・文字のコントラスト
（ライト/ダーク/ハイコントラスト）・Tab 順を機械検証し、OS の「視差効果を減らす」に従います。
項目ごとの現状・既知の制約・実機で確かめる項目は
[`docs/accessibility.md`](docs/accessibility.md) にまとめています。

### 起動モード・ホットキー

- **起動モード**: 設定窓（通常ウィンドウ・不透明、**起動既定**）とルーペ窓
  （透明・実際に画面へかざして見る）を、画面右上の「起動モード」ボタン
  （ダイアログ）のトグルでいつでも切り替えられます。最前面固定・クリックスルー・
  ホットキー一覧も同じダイアログにあります。クリックスルーが ON の間は、復帰方法
  （フォーカス復帰・Esc・トレイ・ホットキー）が画面最上部に常に表示されます。
- **最前面固定・クリックスルー**: それぞれ独立したトグルです。クリックスルー
  を ON にすると下のアプリを直接操作できますが、**トレイもグローバル
  ホットキーも使えない環境では ON にできません**（復帰手段が無いと UI 操作が
  一切できなくなるため）。
- **グローバルホットキー**（ウィンドウが非アクティブでも効く。既定はすべて
  Ctrl+Alt+Shift + キー）:
  - **Ctrl+Alt+Shift+C**: クリックスルーの切替
  - **Ctrl+Alt+Shift+O**: 押している間だけ原画を表示（選択中のフィルタは
    変更しません）
  - **Ctrl+Alt+Shift+Esc**: 非常口 — 全フィルタ停止・クリックスルー解除・
    最前面解除・ルーペ窓を表示/前面化を一括実行
  - **Ctrl+Alt+Shift+L**: ルーペ窓の表示/非表示
- **アプリ内キー操作**（ウィンドウにフォーカスがある間だけ有効）:
  - **`/`**: 左カラムの検索欄（見え方を検索）にフォーカスを移す
  - **`↑` / `↓`**: 一覧（色覚 7 型 + advanced 30 フィルタ。検索・カテゴリで絞っているときは
    見えている行だけ）を逆送り/順送り。体験プリセットは送らない
  - **`←` / `→`**: 選択中フィルタの強度を 5% 刻みで増減
  - **`Esc`**: クリックスルーを解除
  - **`Cmd+V`（macOS）/ `Ctrl+V`（Linux）**: クリップボードの画像をプレビューの原画として貼り付け
    （#97。他のキーと違い、ボタンやスライダーにフォーカスがあっても効く。奪わないのはテキスト入力のときだけ）

  テキスト入力・ボタン・スライダー・一覧の行などにフォーカスがある間は、
  `/` `↑↓` `←→` は奪わず、その部品自身の操作を優先します。一覧の行にフォーカスがある間
  （キーボードで行を選んだあとなど）は `↑↓` が隣の行への移動になります。その間の `←→` 1 回目は
  強度を変えず（体験プリセットの行も同じ。広幅・狭幅とも）、フォーカスが行の外（画面のショートカット受け口。色覚を選んで「2×2 で比較」の切替が出て
  いても同じ）へ出て、次の `←→` から強度が動きます。切替・サンプル・スライダーなど他のカラムへは
  Tab で移れます。行をマウスで選んだ場合は最初から `←→` が効きます。
- **ルーペ窓 HUD**（#79。ルーペ窓モードのときだけ、窓の縁に出る小さな
  ツールバー）: 症状名・強度、受診喚起アイコン（喚起があるときだけ表示。押すと
  免責文を含む全文をダイアログ表示）、原画比較ボタン（押している間だけ原画と
  比較。#63 の bypass を共有）、設定を開くボタン。全画面では自動的に隠れ、
  窓の縁にマウスを近づけると再表示する。詳細は `docs/ARCHITECTURE.md`
  「ルーペ窓 HUD」参照。

## やらないこと（非目標）

- ue は診断・スクリーニング・色覚検査を行いません（受診喚起（体験プリセット・
  advanced フィルタのどちらも）は一般的な案内であり、診断ではありません。
  UI にもその旨を明記します、#76）。
- 色の補正（Daltonization）は、現時点ではしません（シミュレーション専用です）。
- 画像や画面を端末の外に送りません。テレメトリも持ちません。ユーザー画像
  （#78）もディスクに保存せず、メモリ上のデコード結果だけを扱います。
- 動画のエクスポートはしません。
- 運動障害と認知障害は、sensus に正本ができるまで扱いません。

## セットアップ

```bash
git clone https://github.com/kako-jun/universal-experience.git
cd universal-experience
flutter pub get
flutter run
```

Rust は `rust/` の `cargo test` / clippy、flutter_rust_bridge の codegen に加え、
`flutter run` / `flutter build macos` / `flutter build linux` でのビルドにも
必要です（`rust_builder/` の cargokit 統合が同梱まで自動で行う、#55。詳細は
`docs/GETTING_STARTED.md`）。

`flutter pub get` は `pubspec.lock` に固定したバージョン（`file_selector`/
`desktop_drop`/`pasteboard` 等のネイティブ実装込み）を前提にしています。`pubspec.lock`
を消して解決し直すと、意図しないメジャーバージョンの差分（プラットフォーム
実装の挙動差など）を踏む可能性があります。

## 技術スタック

- Flutter 3.38.4+（`pubspec.lock` の `sdks` 準拠。`pubspec.yaml` の
  `sdk: '>=3.3.0 <4.0.0'` は flutter_rust_bridge の生成物が要求する下限にすぎない）
- Provider (状態管理)
- Material Design 3（色は `colorScheme` のロールのみ。OS のハイコントラスト設定に追従するテーマあり。
  UI 設計原則は [`DESIGN.md`](DESIGN.md)）
- 多言語化は `flutter_localizations` + ARB（`lib/l10n/app_en.arb` / `app_ja.arb`、ja/en）
- 色覚・複合症状のアルゴリズム正本は [`sensus-core`](https://crates.io/crates/sensus-core)（Rust crate）。
  ue は flutter_rust_bridge 経由で消費（フィルタ・`experiences()` 等。詳細は `docs/sensus-integration.md`）
